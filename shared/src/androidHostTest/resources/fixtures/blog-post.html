Notes on Writing Small Commits

A commit should tell one story. When a change mixes a refactor with a fix and a new feature, reviewers lose the thread and bisecting becomes guesswork.

Keep the build green

Every commit on the main branch should build and pass the tests. That keeps git bisect useful and makes reverting a single change painless.

git add -p
git commit -m "Fix crash when the list is empty"

Small commits are not about counting lines; they are about one reason to change per commit.
